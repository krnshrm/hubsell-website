# Knowledge article visuals: the app drawn in HTML

Owner decision 2026-11-16 (knowledge-base plan A4-now): articles show the real app as HTML
drawings with demo data. No screenshots, no Scribe images or walkthrough embeds, no uploads.
The CSS kit is the `.kb-ui` block in `src/pages/knowledge/[slug].astro`.

## Rules

1. **Copy the app, do not invent it.** Read the screen's component in hubsell-client `main`
   (`git -C ../hubsell-client show origin/main:<path>`) and its labels in
   `src/i18n/messages/en/*.json`. Every label, button and column name in a drawing is the app's
   English text, word for word. Leave out what the step does not need (columns, menu items),
   but never rename.
2. **Demo data only.** Made-up people and companies: Anna Berger, Tom Fischer, Lena Vos,
   Northwind Logistics, Brightpath Software, Kestrel Analytics; emails `@example.com`. Never
   customer data, team names, real LinkedIn URLs, internal hosts, IPs, env vars, queue names,
   data provider names or competitor names.
3. **One drawing per screen that matters**, usually 2 to 5 per article, not one per click.
   Mark the thing the step tells you to use with `is-marked` (orange outline), and use
   `kb-ui__num` badges when one drawing covers several steps.
4. **Accessible:** the outer `.kb-ui` has `role="img"` and an `aria-label` that says what the
   screen shows and what is marked; everything inside it has `aria-hidden="true"`.
5. **Phone width:** below 560px the sidebar hides and tables scroll. Keep drawings to what fits;
   check at 375px.
6. Wrap every drawing in `<figure class="kb-figure">` with a `<figcaption>`. The address bar
   shows `app.hubsell.com/<real route>`.
7. Each article lists the app files its drawings and text come from in a comment at the top of
   the body (`<!-- sources: ... -->`), so `/update-kb` can find stale ones later.

## Pieces

| Class | What |
|---|---|
| `kb-ui` | the drawing; holds `kb-ui__bar` (browser bar with `kb-ui__url`) and the screen |
| `kb-ui__app` > `kb-ui__nav` + `kb-ui__main` | the app with its sidebar (`kb-ui__logo`, `kb-ui__group`, `kb-ui__item`, `.is-active`) |
| `kb-ui__toolbar` + `kb-ui__h` | page title row with buttons |
| `kb-ui__btn` (`.is-primary`) | button |
| `kb-ui__tabs` > `kb-ui__tab` (`.is-active`) | tabs |
| `kb-ui__tablewrap` > `table.kb-ui__table` (`tr.is-selected`) | table |
| `kb-ui__badge` (`.is-success`, `.is-warning`, `.is-info`, `.is-danger`) | status pill |
| `kb-ui__check` + `kb-ui__box` (`.is-on`) | checkbox with label and hint |
| `kb-ui__field` > `b` + `kb-ui__input` (`.is-placeholder`, `.is-select`) | form field |
| `kb-ui__switch` (`.is-on`) | toggle |
| `kb-ui__menu` > `span` (`.is-sep`, `.is-danger`) | dropdown or actions menu |
| `kb-ui__overlay` > `kb-ui__card` | dialog over the dimmed page |
| `kb-ui__stage` > `kb-ui__card` | a page with one centred card (login, consent) |
| `kb-ui__alert` (`.is-info`) | warning or info box |
| `kb-ui__canvas` > `kb-ui__node` + `kb-ui__link` | flow editor nodes |
| `kb-ui__row`, `kb-ui__stack`, `kb-ui__muted`, `kb-ui__small`, `kb-ui__label` | layout and text helpers |
| `is-marked`, `kb-ui__num` | orange outline, numbered badge |

The sidebar of the app (from `src/components/app-sidebar.tsx` and `messages/en/nav.json`):
groups **Source & Enrich** (Lists, Searches, Contacts) and **Orchestrate & Engage** (Flows,
Tasks). The profile icon menu (`messages/en/userMenu.json`): Credits, User settings, Company
settings, Plan & usage, Integrations, Suppression, MCP, Language, Roles & permissions, Log out.

## Checking a drawing

`npm run build`, then open `dist/knowledge/<slug>/index.html` in a browser at desktop width and
at 375px. Without a server: copy the page, point `/_astro/` at `dist/_astro/` with `file://`
paths, and screenshot it with headless Chrome (minimum window width is 500px, so put the page in
a 375px `<iframe>` for the phone check).
