### Why `cta_click` is 0

This is a tracking bug, not low traffic.

- `src/scripts/track.ts` fires `cta_click` only when a link's path equals the path
  of `SIGNUP_URL` or `DEMO_URL` exactly. Both are `'/book-a-call'` in
  `src/data/site.ts` (no trailing slash).
- Commit `ab73734` (2026-09-29) added a `build:done` hook in `astro.config.mjs`
  that rewrites internal hrefs in `dist` to the trailing-slash form. The live
  `/pricing/` page now has 10 CTAs, all `href="/book-a-call/"`.
- `'/book-a-call/' === '/book-a-call'` is false, so no CTA anywhere on the
  production site can fire `cta_click`. This has been true for every visitor since
  the 2026-09-30 deploy, the same deploy that started loading GTM, so there is no
  usable `cta_click` data at all yet.
- `form_start` arrives (4 events), which shows the dataLayer to GTM to GA4 path
  itself works. Only the CTA matching is broken.

Side note: GA4 shows 1 `cta_click` and some `session_start` events on www before
GTM loaded (2026-09-25 to 09-29). Not explained by this run; worth a look only if it
recurs.
